# SplatWorks Desktop 1.0 release contract

The core PDF/Cipher suite and the six independent desktop tools use the same local
file-writing, close protection, connection gate and packaging infrastructure.
The core release candidate is `v1.0.0-rc.8`. The standalone tools' common 1.0
candidate is `tools-v1.0.0-rc.3`. Candidates remain prereleases until publisher
signing and physical-device validation are complete.

| Distribution | 1.0 workflow |
| --- | --- |
| SplatWorks Desktop | PDF import/edit/export, English/Spanish OCR, CipherSplat CS4 and OpenPGP, native file/folder destinations |
| GIFsplat | Frame import/order/timing, animated GIF export, portable editable projects |
| CipherSplat | File/folder/text encryption and authenticated decryption, OpenPGP, compatible CS4 packages |
| QRSplat | Standard text/link/email/phone/Wi-Fi QR generation, PNG/SVG export, portable designs excluding Wi-Fi passwords |
| ImageSplat | Local image composition, text/layers/crop/blur, PNG/GIF export, portable projects, bundled Fast photo removal and lettering |
| AudioSplat | Multitrack editing/effects, WAV/MP3 exports, portable projects with embedded audio, independent transcript protection |
| VideoSplat | Layered timelines, titles/captions, audio mixing, local video export with supported codecs, portable projects and bundled FFmpeg conversion |

No automatic updater, cloud account, background document recovery or remote
application-code download is part of the 1.0 contract. Optional connections default
off. Speech models may be explicitly downloaded within the connection gate's size
limits or selected as local GGML files. Generated transcripts remain in memory
until explicitly saved or added to a project.

Recording, screen/system audio, hardware acceleration and additional export codecs
depend on the platform webview, available devices and permissions. A successful
synthetic test does not qualify those workflows on physical hardware. VideoSplat
portable projects support 256 MB of source media and 360 MB per project file;
large-media and codec constraints remain documented application limits.

## Engineering checks

The automated release workflows build Linux, Windows and universal Mac packages.
They exercise native saves, encrypted restoration, actual encoded/exported files,
portable project reopening, no-network workflows, and installation/package checks.
Browser regression checks cover save failure/cancellation, dialog controls, dirty
work, damaged project rejection and browser/desktop interoperability. Go save tests
and vulnerability scanning remain required. Mac disk-image creation retries bounded
service-contention failures; permanent failures still stop publication.

The PDF/Cipher binary excludes standalone media engines. Each independent app
contains its own selected tools and offline dependencies. Source manifests pin
imported files and original notices; packaging verifies the committed snapshots.

## Stable publication

1. Run `python3 scripts/release-readiness.py` and configure the missing signing
   variables/secrets directly in GitHub using [SIGNING.md](SIGNING.md).
2. Run signed candidate workflows and verify the publisher signatures/notarization.
3. Complete and record [physical-device validation](VALIDATION.md) for the exact
   candidate, platform and architecture. Approval for the core suite does not
   approve the independent tools.
4. Set the applicable physical-validation approval variable only after those
   results pass. Publish `v1.0.0` and/or `tools-v1.0.0` from the validated source.
5. Verify the public packages and checksums. Stable workflows enforce signing and
   physical-approval configuration; an unsigned candidate is never promoted by
   merely removing its prerelease label.
